Dentrix Follow-Up Integration for Unscheduled Treatment

A useful Dentrix connection should help the team see whether treatment is still open and whether the relevant visit is already booked. It is not required to estimate the leak or to work a first batch from the report you already run.

What data matters for follow-up

An unscheduled-treatment workflow does not need every field in the practice-management system. The core questions are whether a treatment plan or treatment-planned procedure still exists, whether the relevant appointment is already on the book, whether the patient is only on an unscheduled list, and what the last outreach already was.

Those are the same questions the Open Dental integration guide asks of treatment plans, appointment status, and planned appointments. Dentrix can answer them from reports today and, where a vendor has an approved scope, from the API objects above. A production connection still has to be tested against the office’s product, version, and permissions.

What you can do before any API

Integration is a way to keep status current. It is not the starting line.

  1. Pull the report with the steps on the Dentrix unscheduled treatment report page, or the Open Dental Treatment Finder if that is your system.
  2. Have a person confirm that each case in a short batch is still open.
  3. Assign one owner, one next action, and one date.
  4. Estimate the size of the leak with aggregate counts in the revenue leak calculator. No patient-level data is required.

The longer version of that start is start dental follow-up without a PMS integration. If the numbers justify a connected workflow later, you will already know which status checks matter.

How an unscheduled treatment workflow can work

  • Treatment plan
  • Validate status
  • Eligible queue
  • Follow-up
  • Reply
  • Schedule / route
  • Close

A practical flow finds active treatment context, checks appointment state before any outreach, and places only the still-eligible cases into a recovery queue. A reply can be routed by scheduling need, timing, cost concern, or a question that needs a person. If the relevant visit gets scheduled, the workflow should stop or update rather than continue an outdated sequence.

Praxora is built for that recovery loop: missed calls, unscheduled treatment, and overdue recall, with human review before outreach. It is not patient intake, a virtual waiting room, or a post-visit survey product.

Why status checks matter

A follow-up list goes stale if nobody re-checks the practice-management system. Before a message goes out, a person or a connected workflow should confirm that the treatment opportunity is still open and that the patient has not already scheduled, completed, or declined it.

Desktop Dentrix makes one version of this mistake easy to see. The Unscheduled Treatment Plans report can mark a patient with an S when they already have an appointment for other treatment-planned work. That appointment does not close every remaining procedure. A connected workflow that only asks “does this patient have any future appointment?” will suppress the wrong cases, or it will keep texting people who booked.

What a vendor should show in a demo

  • Which product it supports: desktop Dentrix, Dentrix Ascend, or both.
  • How treatment opportunities are identified, and from which report or API object.
  • How it tells an appointment for other work apart from the procedure you are following up.
  • What happens when the patient schedules after entering the queue.
  • How replies are routed and who owns the next action.
  • Whether anything is written back, and under what permission.
  • How opt-outs are enforced, and how a clinical or sensitive reply is handed to a person.
  • What the office must sign or install before the connection works.

Also ask for the first-year cost of the connection separately from the monthly workflow fee. The pricing guide is the place to compare that with other follow-up tools. If you want a directional estimate before any of that, use the calculator.

Frequently asked questions

Does Praxora require a Dentrix API to start?

No. The calculator and the free follow-up leak review use aggregate practice figures. They do not connect to Dentrix or Dentrix Ascend and they do not require patient-level data. A live outreach or PMS setup is a separate agreement.

Is Dentrix Ascend the same integration as desktop Dentrix?

No. Desktop Dentrix and Dentrix Ascend are different products with different partner programs. A vendor should say which product it supports, which data it reads, and whether it can write anything back.

Should follow-up stop when a Dentrix appointment is booked?

Yes. A recovery workflow should re-check current status and stop or update outreach when the relevant appointment has been scheduled. An appointment for unrelated work does not by itself close every open treatment plan.
